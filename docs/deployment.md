# Deployment (Task 15)

> **Status.** The configuration files below are valid and the application was verified locally against real MongoDB, but **nothing has been deployed from the build environment** (no access to Atlas, Render, Vercel or Docker). Treat this as a tested-locally runbook; the first real deployment may need small adjustments.

Target topology (all have free tiers): **MongoDB Atlas** (database) · **Render** (API + AI service) · **Vercel** (React app).

## 0. Generate secrets

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('base64'))"   # JWT_SECRET
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"      # AI_SERVICE_TOKEN (use the same value on both Render services)
```

## 1. MongoDB Atlas (Activity 15.3)

1. Create a free **M0** cluster. *Database Access* → add a user with a strong password (URL-encode special characters such as `@` → `%40` in the connection string).
2. *Network Access* → allow `0.0.0.0/0` (Render's free tier has no fixed outbound IPs). Compensate with the strong password and a least-privilege user (`readWrite` on one database).
3. *Connect → Drivers* → copy the string and add the database name:
   `mongodb+srv://<user>:<password>@<cluster>.mongodb.net/adaptlearn?retryWrites=true&w=majority`

## 2. Render: API and AI service (Activities 15.1, 15.5)

1. Push the repository to GitHub (Activity 15.4). Confirm no `.env` file is committed.
2. Render → *New → Blueprint* → pick the repo; it reads `render.yaml` and proposes two web services.
3. Fill the prompted variables:

| Service | Variable | Value |
|---|---|---|
| both | `AI_SERVICE_TOKEN` | the same 64-hex-character secret |
| both | `MONGO_URI` | the Atlas string. The AI service connects to the same cluster; it uses `MONGO_DB=adaptlearn` for its `ai_*` collections |
| api | `JWT_SECRET` | generated by the blueprint, or your own (≥ 32 bytes) |
| api | `ADMIN_EMAIL`, `ADMIN_PASSWORD` | your administrator login (password 12-72 characters) |
| api | `AI_SERVICE_URL` | `https://<ai-service-name>.onrender.com` (no trailing slash) |
| api | `CLIENT_URL` | your Vercel URL, e.g. `https://adaptlearn.vercel.app`: **set after step 3**, then redeploy |
| api | `SEED_ON_BOOT` | `true` for the first deploy only; then set `false` |

4. Verify: `curl https://<api>.onrender.com/api/health` → `{"status":"ok",...}` and `/api/health/ready` → `database: "connected"`, `ai: "up"`.

Notes: free web services **sleep after ~15 minutes idle** (first request takes 30-60 s; Socket.IO reconnects by itself). Render supports WebSockets on web services. The platform sets `PORT`; the API reads it.

## 3. Vercel: React app (Activities 15.2, 15.6, 15.7)

1. Vercel → *Add New Project* → import the repo → **Root Directory: `client`**, framework *Vite* (also set by `client/vercel.json`).
2. Environment variables:
   * `VITE_API_URL` = `https://<api>.onrender.com/api/v1`
   * `VITE_SOCKET_URL` = `https://<api>.onrender.com`
3. Deploy. `vercel.json` provides the **single-page-app fallback** (deep links such as `/courses/introduction-to-database-systems` and page refreshes work), long-cache headers for hashed assets, and the security headers/CSP.
4. Copy the production URL into Render's `CLIENT_URL` and redeploy the API (**CORS and Socket.IO accept only that origin**, Activity 15.8). Use several origins separated by commas (for example a preview domain).
5. If you use a custom API domain that is not `*.onrender.com`, add it to `connect-src` in `client/csp.js`, `client/nginx.conf` and `client/vercel.json` (and keep the three identical).

## 4. Docker (alternative, single host)

```bash
cp .env.example .env     # JWT_SECRET, AI_SERVICE_TOKEN, ADMIN_PASSWORD, CLIENT_URL=http://localhost:8080
docker compose up --build
```

Services: `mongo` (volume `mongo-data`), `ai-service`, `api`, `web` (nginx serving the SPA and proxying `/api` and `/socket.io`). `docker compose down -v` also deletes the database volume.

## 5. Post-deployment smoke test (Activity 15.10)

1. Open the Vercel URL → register a student → sign in.
2. Sign in as the admin → *Courses* → open *Introduction to Database Systems* → **Attach videos from a YouTube playlist** (paste the NPTEL-NOC IITM playlist URL) so lessons have video.
3. As a student: enrol, open a lesson, mark complete, ask the tutor "Why are B+ tree leaves linked?" (should cite *B+ trees on Disks*), take a quiz, open *Dashboard* → study plan.
4. Two browsers (two students enrolled in the same course): send a message in the course chat and a direct message; the other sees it **without refreshing**, and a notification appears on any page.
5. As admin publish a course; online students receive a toast.
6. Run the Postman collection against production: `newman run postman/adaptlearn.postman_collection.json --env-var baseUrl=https://<api>.onrender.com --env-var adminEmail=<admin> --env-var adminPassword=<password>` (it creates and removes its own data; run it **before** real users exist, or note that it adds one test student).

## 6. Environment variables

See `server/.env.example`, `ai-service/.env.example`, `client/.env.example` and `.env.example` (compose). The API **refuses to start** if `JWT_SECRET` is shorter than 32 bytes, `MONGO_URI` is missing, or `ADMIN_EMAIL`/`ADMIN_PASSWORD` are not provided together; the AI service refuses `ENVIRONMENT=production` with a token shorter than 24 characters.

## 7. Troubleshooting (Activity 15.11)

| Symptom | Likely cause and fix |
|---|---|
| Browser console: CORS error | `CLIENT_URL` on the API does not exactly match the page origin (scheme + host, no trailing slash). Fix and redeploy. |
| Chat shows "Reconnecting" | `VITE_SOCKET_URL` missing or wrong; or the API is cold-starting (wait a minute). |
| `/api/health/ready` returns `ai: "down"` | `AI_SERVICE_URL` wrong, tokens differ, or the AI service is asleep. Tutor/plan return 503 until it is up; nothing else is affected. |
| Tutor says the course "has not been indexed" | Run *Re-index for AI tutor* in the course editor (the AI service lost its in-memory index, or `MONGO_URI` is not set on it). |
| 401 immediately after sign-in | Clock skew or a different `JWT_SECRET` between instances. |
| Atlas "connection timed out" | IP not allowed (Network Access) or the password has unescaped special characters. |
| Page refresh gives 404 on Vercel | Root Directory is not `client`, so `vercel.json` was not applied. |
| Seeded courses appear twice | They cannot: seeding matches titles. Check that `SEED_ON_BOOT` was not combined with courses renamed by an admin. |

## 8. Operations

* **Logs:** one line per request with a request id; clients can quote the `requestId` from an error body.
* **Backups:** use Atlas snapshots (paid tiers) or `mongodump`.
* **Rotate secrets:** changing `JWT_SECRET` signs everyone out; changing `AI_SERVICE_TOKEN` requires updating both services.
